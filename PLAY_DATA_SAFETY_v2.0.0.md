# Play Data Safety — CraftLife v2.0.0 (draft answers, verify before submitting)

Derived from what the code actually collects (desktop API + Supabase
schema). If a future feature changes collection, update this file first.

| Data type | Collected? | Shared? | Purpose | Notes |
|---|---|---|---|---|
| Email address | Yes (optional) | No | Account (Supabase Auth) | Only when user links a cloud account |
| User IDs (cloud UUID) | Yes (optional) | No | Sync identity, social | Generated by Supabase Auth |
| Password | Processed, never stored in app storage | No | Authentication | Held by Supabase Auth (hashed server-side); desktop passwords hashed locally |
| Health & fitness (sport, food, water, sleep logs) | Yes | No | App functionality | User's own tracker data; synced only if cloud linked |
| App activity (habits, tasks, notes, economy, game progress) | Yes | No | App functionality | Core tracker data |
| Messages (friend/guild chat) | Yes (optional) | With chat participants only | Social features | Visible to conversation members by design |
| Device push token (FCM) | Yes (optional) | Sent to FCM to deliver notifications | Notifications | Only when push is configured by the operator |
| Diagnostics / crash data | No third-party SDK | — | — | No analytics/ads SDKs in the app |
| Advertising ID | No | No | — | Not accessed |
| Location | No | No | — | Not requested |
| Photos/files | User-selected note attachments | No | App functionality | Stored in user's own Supabase Storage bucket |

- All cloud traffic is HTTPS (Supabase). Data encrypted in transit: Yes.
- Data deletion: users can unlink cloud and request deletion via the
  operator contact; local data is deletable in-app (Settings → data).
- Account creation is optional; the app is fully usable offline/local.
